# Data Model: Connect Frontend Authentication and Chat to Backend APIs

**Date**: 2025-12-23
**Feature**: 001-connect-frontend-backend-apis
**Purpose**: Define frontend and backend data structures, validation rules, and state transitions

---

## Overview

This feature integrates frontend React components with existing backend FastAPI endpoints. The data model focuses on **frontend state management** (React contexts, localStorage) and **API contract compliance** (matching backend Pydantic models). No backend schema changes are required.

---

## 1. Authentication Entities

### 1.1 User (Frontend State)

**Location**: `AuthContext.tsx` state, localStorage

**Purpose**: Represents the authenticated user in the frontend application

**Fields**:
```typescript
interface User {
  id: string;          // User UUID from backend (user_id in LoginResponse)
  email: string;       // User's email address
}
```

**Validation Rules**:
- `id`: Non-empty string, UUID format (validated by backend)
- `email`: Valid email format (validated by backend at login)

**Storage**:
- **State**: React Context (`AuthContext`)
- **Persistence**: `localStorage.getItem('user')` as JSON string
- **Lifecycle**: Created on login, cleared on logout/token expiry

**State Transitions**:
```
[No User] --login()--> [User Created + Stored]
[User Exists] --logout()--> [User Cleared from State + localStorage]
[User Exists] --token expired --> [User Cleared + Redirect to Sign-In]
```

---

### 1.2 Authentication Token (Frontend State)

**Location**: `AuthContext.tsx` state, localStorage

**Purpose**: JWT access token for authenticating API requests (currently not used since /chat has no auth)

**Fields**:
```typescript
interface AuthToken {
  token: string;       // JWT access token (bearer token)
}
```

**Validation Rules**:
- `token`: Non-empty string, JWT format (not validated client-side, trusted from backend)
- **Note**: Token expiry is not checked client-side; backend returns 401 for expired tokens

**Storage**:
- **State**: React Context (`AuthContext.token`)
- **Persistence**: `localStorage.getItem('authToken')` as string
- **Lifecycle**: Created on login, cleared on logout/401 error

**State Transitions**:
```
[No Token] --login()--> [Token Stored + User Authenticated]
[Token Exists] --logout()--> [Token Cleared]
[Token Exists] --401 error --> [Token Cleared + Redirect]
```

---

### 1.3 Login Request (API Contract)

**Location**: Frontend `AuthContext.login()` method → Backend `/auth/login`

**Purpose**: Credentials sent to backend for authentication

**Fields**:
```typescript
interface LoginRequest {
  email: string;       // User's email
  password: string;    // User's password (plain text, sent over HTTPS)
}
```

**Validation Rules** (Frontend):
- `email`: Non-empty, valid email format (basic regex check recommended)
- `password`: Non-empty (min 8 chars check recommended, but backend enforces)

**Backend Validation** (Pydantic):
- Defined in `auth/models/request.py:UserLoginRequest`
- Email format validation, password hashing comparison

**Example**:
```json
{
  "email": "student@example.com",
  "password": "SecurePass123"
}
```

---

### 1.4 Login Response (API Contract)

**Location**: Backend `/auth/login` → Frontend `AuthContext.login()`

**Purpose**: Authentication result with access token

**Fields**:
```typescript
interface LoginResponse {
  access_token: string;  // JWT bearer token (24-hour validity per spec assumptions)
  user_id: string;       // User UUID
  token_type: string;    // Always "bearer"
}
```

**Validation Rules** (Backend):
- Defined in `auth/models/request.py:UserLoginResponse`
- `access_token`: Generated by `LoginService.authenticate_user()`
- `user_id`: Existing user UUID from database
- `token_type`: Literal value "bearer"

**Example**:
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "token_type": "bearer"
}
```

## 2. Chat Entities

### 2.1 Chat Message (Frontend State)

**Location**: Chat history state (to be implemented in `ChatContext` or `ChatWindow`)

**Purpose**: Represents a single message in the chat conversation

**Fields**:
```typescript
interface ChatMessage {
  id: string;                        // Unique message ID (generated client-side: `msg-${Date.now()}-${Math.random()}`)
  content: string;                   // Message text (user input or AI response)
  sender: 'user' | 'ai';             // Message sender type
  timestamp: string;                 // ISO 8601 timestamp (e.g., "2025-12-23T14:30:00Z")
  status: 'sending' | 'delivered' | 'failed';  // Message delivery status (user messages only)
  agentName?: string;                // AI agent name (for AI messages only, from ChatResponse.agent_name)
}
```

**Validation Rules**:
- `id`: Unique across session (client-generated, no backend validation)
- `content`: 3-10,000 characters (validated per FR-008 before sending)
- `sender`: Enum: 'user' | 'ai'
- `timestamp`: ISO 8601 format (generated via `new Date().toISOString()`)
- `status`: Enum, only applicable for user messages (AI messages always 'delivered')

**Storage**:
- **State**: React component state (ChatWindow messages array)
- **Persistence**: `localStorage.getItem('chatHistory')` as JSON array
- **Lifecycle**: Appended during chat session, cleared on logout (FR-012)

**State Transitions** (User Messages):
```
[New Message] --send()--> [status: 'sending']
[Sending] --API success --> [status: 'delivered']
[Sending] --API error --> [status: 'failed']
[Failed] --retry()--> [status: 'sending']
```

**State Transitions** (AI Messages):
```
[User message sent] --API response --> [AI message created with status: 'delivered']
```

### 2.2 Chat Request (API Contract)

**Location**: Frontend `ChatService.sendMessage()` → Backend `/chat`

**Purpose**: User message sent to AI tutor

**Fields**:
```typescript
interface ChatRequest {
  message: string;     // User's question or input (3-10,000 chars)
  sessionId?: string;  // Optional session ID (not currently used by backend)
}
```

**Validation Rules** (Frontend):
- `message`: Trimmed, 3-10,000 characters (FR-008)
- `sessionId`: Optional, ignored by backend (future feature)

**Backend Validation** (Pydantic):
- Defined in `backend/src/backend/models.py:ChatRequest`
- Message length validation enforced (422 error if invalid)

**Example**:
```json
{
  "message": "What is ROS 2 and how does it differ from ROS 1?"
}
```

### 2.3 Chat Response (API Contract)

**Location**: Backend `/chat` → Frontend `ChatService.sendMessage()` callback

**Purpose**: AI tutor's response to user's question

**Fields**:
```typescript
interface ChatResponse {
  response: string;      // AI-generated response text
  agent_name: string;    // Name of the AI agent (e.g., "AI Tutor")
  timestamp: string;     // Server-generated timestamp (ISO 8601)
}
```

**Validation Rules** (Backend):
- Defined in `backend/src/backend/models.py:ChatResponse`
- `response`: Generated by AI agent, no length limit
- `agent_name`: Default "AI Tutor" (from tutor_agent.agent.name)
- `timestamp`: Auto-generated by backend

**Example**:
```json
{
  "response": "ROS 2 (Robot Operating System 2) is a complete rewrite of ROS 1 designed for production robotics...",
  "agent_name": "AI Tutor",
  "timestamp": "2025-12-23T14:30:15Z"
}
```

### 2.4 Rate Limit State (Frontend State)

**Location**: `ChatService` instance, localStorage (optional persistence)

**Purpose**: Track request timestamps to enforce client-side rate limiting

**Fields**:
```typescript
interface RateLimitState {
  requests: number[];    // Array of timestamps (milliseconds since epoch)
  maxRequests: number;   // Max requests allowed (default: 3)
  windowMs: number;      // Time window in milliseconds (default: 30000 = 30 seconds)
}
```

**Validation Rules**:
- `requests`: Filtered to remove timestamps older than `windowMs`
- `maxRequests`: Positive integer (3 per spec)
- `windowMs`: Positive integer (30000 per spec)

**Storage**:
- **State**: `ChatService` instance variable
- **Persistence**: `localStorage.getItem('chatRateLimit')` (optional, for cross-tab rate limiting)
- **Lifecycle**: Updated on each request, cleared on logout

**Logic**:
```typescript
isRateLimited(): boolean {
  const now = Date.now();
  this.rateLimit.requests = this.rateLimit.requests.filter(t => now - t < this.windowMs);
  if (this.rateLimit.requests.length >= this.maxRequests) return true;
  this.rateLimit.requests.push(now);
  return false;
}
```

## 3. Error Entities

### 3.1 API Error Response (Backend)

**Location**: All API endpoints (`/auth/login`, `/chat`)

**Purpose**: Standard error response format from FastAPI

**Fields**:
```typescript
interface APIError {
  detail: string;        // Human-readable error message
  status?: number;       // HTTP status code (sometimes included)
}
```

**Common Error Responses**:

| Status Code | detail | Trigger |
|-------------|--------|---------|
| 401 | "Invalid email or password" | Incorrect credentials |
| 422 | "Validation error" | Invalid request payload |
| 429 | "Rate limit exceeded" | Too many requests |
| 500 | "Internal server error" | Backend exception |
| 504 | "Request timeout" | Request exceeded 30s |

**Frontend Error Mapping** (per research.md decision 2):
```typescript
function mapErrorToUserMessage(error: APIError): string {
  const { detail, status } = error;
  if (status === 401) return 'Invalid email or password. Please try again.';
  if (status === 422) return 'Invalid message format. Please check your input.';
  if (status === 429) return 'You\'ve sent too many messages. Please wait before trying again.';
  if (status === 500) return 'The service is temporarily unavailable. Please try again later.';
  if (status === 504) return 'Request timeout. Please try again later.';
  return 'An unexpected error occurred. Please try again.';
}
```

## 4. React Context State Models

### 4.1 AuthContextType

**Location**: `frontend/src/contexts/AuthContext.tsx`

**Purpose**: Authentication state and actions

**Fields**:
```typescript
interface AuthContextType {
  user: User | null;                          // Current authenticated user
  token: string | null;                       // JWT access token
  login: (email: string, password: string) => Promise<void>;   // Login action
  register: (email: string, password: string) => Promise<void>; // Register action

```

**State Lifecycle**:
- **Mount**: Restore user and token from localStorage
- **Login**: Fetch token from backend, update state + localStorage
- **Logout**: Clear state + localStorage + chatHistory

## 5. Data Flow Diagrams

### 5.1 Authentication Flow

```
[User enters email/password]
    ↓
[Frontend validates format]
    ↓
[AuthContext.login(email, password)]
    ↓
[POST /auth/login with {email, password}]
    ↓
[Backend validates credentials]
    ↓
[Success: LoginResponse {access_token, user_id}]
    ↓
[AuthContext stores token + user in state + localStorage]
    ↓
[isAuthenticated = true]
    ↓
[Redirect to protected route or show success]
```

### 5.2 Chat Message Flow

```
[User types message in ChatWindow]
    ↓
[Frontend validates length (3-10,000 chars)]
    ↓
[ChatService.sendMessage(message, onResponse)]
    ↓
[Check client-side rate limit]
    ↓
[POST /chat with {message}]
    ↓
[Backend processes with AI agent]
    ↓
[Success: ChatResponse {response, agent_name, timestamp}]
    ↓
[onResponse(data.response) callback]
    ↓
[ChatWindow appends AI message to history]
    ↓
[Update localStorage chatHistory]
```

### 5.3 Logout Flow

```
[User clicks logout button]
    ↓
[AuthContext.logout()]
    ↓
[Clear user + token from state]
    ↓
[localStorage.removeItem('authToken')]
    ↓
[localStorage.removeItem('user')]
    ↓
[localStorage.removeItem('chatHistory')] ← FR-012
    ↓
[localStorage.removeItem('chatRateLimit')]
    ↓
[isAuthenticated = false]
    ↓
[Redirect to sign-in page]
```

## 6. Validation Summary

| Entity | Validation Point | Rules | Error Handling |
|--------|------------------|-------|----------------|
| LoginRequest.email | Frontend + Backend | Non-empty, email format | Display "Invalid email format" |
| LoginRequest.password | Frontend + Backend | Non-empty (min 8 chars recommended) | Display "Password required" |
| ChatRequest.message | Frontend + Backend | Trimmed, 3-10,000 chars | Display "Message must be 3-10,000 characters" |
| ChatMessage.content | Frontend (display) | Sanitize HTML to prevent XSS | Escape HTML entities |
| AuthToken | Backend (on API calls) | JWT validity, expiry | 401 → logout + redirect |
| RateLimit | Frontend + Backend | Max 3 requests/30s | Display "Rate limit exceeded. Please wait." |

## 7. Storage Schema

### localStorage Keys

| Key | Type | Purpose | Cleared On |
|-----|------|---------|------------|
| `authToken` | string | JWT access token | logout, 401 error |
| `user` | JSON string | User object `{id, email}` | logout, 401 error |
| `chatHistory` | JSON array | Array of ChatMessage objects | logout, session expiry |
| `chatRateLimit` | JSON object | RateLimitState object | logout |
| `chatWidgetState` | JSON object | Widget position/minimize state | Never (persists across sessions) |

**Example localStorage Data**:
```javascript
localStorage.setItem('authToken', 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...');
localStorage.setItem('user', '{"id":"a1b2c3d4-...","email":"student@example.com"}');
localStorage.setItem('chatHistory', '[{"id":"msg-1","content":"Hello","sender":"user",...}]');
localStorage.setItem('chatRateLimit', '{"requests":[1703343000000],"maxRequests":3,"windowMs":30000}');
```

## Summary

This data model defines:
- **4 core entities**: User, AuthToken, ChatMessage, RateLimitState
- **6 API contract interfaces**: LoginRequest, LoginResponse, ChatRequest, ChatResponse, APIError
- **2 React context types**: AuthContextType, ChatContextType
- **5 localStorage keys**: authToken, user, chatHistory, chatRateLimit, chatWidgetState

All entities align with existing backend Pydantic models (no backend changes required). Frontend validation rules enforce spec requirements (FR-008: message length, FR-012: history clearing, etc.).
